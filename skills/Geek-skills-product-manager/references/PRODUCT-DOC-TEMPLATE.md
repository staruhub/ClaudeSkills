- Status: Draft | Approved

## 1. Problem and desired outcome

State the observable problem, who experiences it, and the desired change.

## 2. Primary users and JTBD

Name the primary user and write the job-to-be-done in context.

## 3. Evidence and assumptions

Separate repository/user evidence from assumptions. Include traceable evidence
paths or source identifiers.

## 4. Scope and non-goals

List the minimum in-scope outcome and explicit exclusions.

## 5. User flow and failure recovery

Describe the happy path, important branches, failure states, retry/recovery, and
what the user sees.

## 6. Requirements

Use stable requirement IDs. Each requirement states inputs, behavior, outputs,
and failure handling. Include non-functional requirements where material.

## 7. Success metrics and guardrails

Define metric, population, window, baseline if known, target, and guardrail.
Label proposed numbers as targets rather than facts.

## 8. Risks and dependencies

Record product, data, safety, privacy, operational, and delivery risks with
mitigation or owner.

## 9. Open questions

Separate blocking from non-blocking questions. An approved document must have no
blocking question.

## 10. Acceptance criteria

Write testable, numbered criteria that cover the main flow and failures.

## Decision log

For each decision include ID, decision, rationale, source, and status.

## Implementation boundary

This document does not authorize implementation. The product-manager skill
stops after the approved document is delivered.
